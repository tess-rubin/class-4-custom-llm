# Interpretation and evidence audit

These notes describe the supplied implementation. They are not experimental results.

- **Learning rate:** `0.001` is the configured maximum. A 3,000-step run has 100 warmup steps; the first optimizer step actually uses `0.00001`. Warmup is followed by the supplied cosine schedule with a 10% floor. Report the saved actual rate for the first update.
- **Gradient:** `inspection.json` records the first coordinate's gradient **before** global gradient-norm clipping to 1.0. AdamW sees the clipped gradient. Its momentum, adaptive second moment, numerical epsilon, and decoupled weight decay also affect the update. Do not claim the saved update equals negative learning rate times the recorded gradient or that the saved gradient is the clipped one. Input embeddings and the output classifier share weights, so a token's row can receive output-side gradients even when the token is absent from a training batch's inputs.
- **Vocabulary and case coverage:** training and validation unknown-token rates count token occurrences within their respective corpus splits, excluding BOS/EOS. Eval coverage counts cases with usable vocabulary and context; tied cases are scorable but earn zero. Unknown prompt words or any unknown choice make the entire case unscorable. These quantities have different denominators and meanings.
- **Scores and generated text:** the four-choice score selects the largest of four entries in the full-vocabulary softmax. Those four probabilities are not renormalized to sum to one. The model receives only the prefix, not the choices, key, or explanation. A correct choice need not be the globally most likely next token, and need not appear in the separate free continuation. Ties get zero. Empty output is valid evidence when EOS is sampled immediately.
- **Two generators:** notebook timeline/temperature samples start with BOS, use seed 2026, permit all vocabulary entries, and allow at most 32 generated tokens. Eval/chat continuations start with BOS plus the supplied prefix, mask generated BOS, and allow at most 24 tokens. The latter use seed 2026 plus the case/interaction index. Temperature comparisons use the same trained weights, BOS starting token, and reset seed for each temperature; later paths still diverge as sampled tokens differ. Do not compare these as if they used identical prompts or decoding rules.
- **Loss:** the three saved measurements use fixed panels sampled from the training and validation splits, each containing at most 20 documents. The loss averages non-padding next-token targets, including EOS. It is not a full-corpus loss, a pass rate, or a directly comparable measure between different corpora/vocabularies. Validation sentences share synthetic templates and may share source files with training.
- **Corpus extraction:** the importer splits at sentence-ending punctuation followed by whitespace, and at newlines, then slices units into at most 47 word/punctuation tokens. A multi-sentence teaching example can become several documents, and its negation and correction can land in different contexts or splits. Distinguish authored examples, extracted passages, unique passages, and duplicates removed. An imported root `README.md` is ignored; other Markdown files are literal training text.
- **Separation:** generated classroom sentences containing normalized exact eval prefixes are removed before deduplication, splitting, and vocabulary construction. Imported exact prefixes are rejected. These checks do not establish absence of close paraphrases, copied answers, or semantic leakage. Review original teaching sources as well as the automatic report. Because the fixed public suite informs extension selection, describe it as a development benchmark.
- **Hashes and seeds:** the suite's semantic hash is SHA-256 of sorted-key JSON serialization, not the file-byte SHA-256. The model hash is over sorted state-dictionary names and tensor bytes, not the `.pt` file bytes. Use the right hash for the claim. Each fresh model uses seed 42, but differing vocabulary shapes/IDs can change initial parameters and sampled words. A same-seed pair is not a controlled comparison with identical token identities.
- **Saved evidence:** `model.pt` contains the complete network and saved vocabulary for inference; `checkpoint.json` contains viewer embeddings. Neither includes the optimizer/RNG state needed for an exact resumed training run. `training_summary.elapsed_seconds` measures the training-loop interval, including the halfway/final panel checks and generated samples, but excludes setup, baseline eval, and posttraining artifact work.
- **Attention:** the inspection exports a single head in the first block, computed from trained query/key projections with a causal mask. It is not a complete explanation of the network's decision. The viewer's PCA projects 64 dimensions into a smaller display; cosine-neighbor comparisons use the full vectors.

`scripts/verify_artifacts.py` reads both run directories, their executed notebooks, ZIPs, and optional saved-model eval reruns. It checks fixed source checksums, all 48 case identities and scores across all four result sets, summaries and CSV/JSON consistency, split and vocabulary provenance, panels, complete sample timelines (including empty strings), first-update rate, saved vectors and weights, fresh seed-42 initialization, model/suite identities, complete notebook execution, and ZIP contents. It does not train or write artifacts. Human review is still needed for extraction quality, semantic leakage, sampled-text interpretation, and the learner's own explanations.
